# Requirements: CI/CD パイプライン整備

## 背景

現在の CI/CD パイプラインは基本的なビルド・テスト・リリースを網羅しているが、以下の2つの領域にギャップがある:

1. **ドキュメント不足**: CI/CD に関するドキュメントが CLAUDE.md・README.md に不足しており、新規参加者がパイプラインを理解しにくい
2. **インテグレーションテスト不在**: 165 テスト中 95% が軽量ユニットテスト（スタブベース）であり、IDE プラットフォームを使った統合テストが 6 件のみ。PSI パース・ハイライト・補完等の IDE 機能の回帰テストが不足している

## スコープ

### 1. CI/CD ドキュメント整備

- CLAUDE.md に CI/CD セクションを追加し、ワークフロー一覧・実行方法・トラブルシューティングを記載
- Sphinx ドキュメントに CI/CD ページを追加（開発者向けガイド）

### 2. インテグレーションテスト追加

BasePlatformTestCase / LightPlatformCodeInsightFixtureTestCase を使ったプラットフォームテストを追加し、以下の領域をカバーする:

- **レクサー統合テスト**: testData ファイルを使ったトークナイズ検証
- **パーサー統合テスト**: .res ファイルの PSI ツリー検証
- **ハイライトテスト**: シンタックスハイライトの色分け検証
- **折りたたみテスト**: コード折りたたみ領域の検証
- **構造ビューテスト**: ストラクチャービューのツリー構造検証
- **インデントテスト**: 自動インデントの動作検証

### スコープ外

- JetBrains Marketplace 公開の自動化
- カバレッジ閾値の強制
- Qodana の設定変更
- CI ワークフロー自体の変更（新テストは既存の `./gradlew test` で実行される）

## 受け入れ条件

1. CLAUDE.md の「ビルド・実行コマンド」セクションに CI/CD 情報が追加されている
2. Sphinx ドキュメントに CI/CD ガイドページが存在する
3. `src/test/testData/` ディレクトリにテストデータファイルが配置されている
4. 各テスト領域に最低 1 つの BasePlatformTestCase テストが追加されている
5. `./gradlew clean buildPlugin` が成功する
6. 全テストがパスする
