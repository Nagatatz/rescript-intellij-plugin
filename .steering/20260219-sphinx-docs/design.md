## 2. Technology Choices

| Component | Choice | Rationale |
|-----------|--------|-----------|
| Markup | Markdown via MyST Parser | Lower barrier for contributors vs. reStructuredText |
| Theme | Furo | Modern, built-in dark mode, responsive, well-maintained |
| i18n | sphinx-intl (gettext) | Official Sphinx i18n approach; .po files are standard |
| Deployment | GitHub Pages + actions/deploy-pages@v4 | Consistent with existing CI patterns |
| Copy button | sphinx-copybutton | UX improvement for code blocks |
| UI components | sphinx-design | Cards, grids, tabs for feature pages |

## 3. Sphinx Configuration Design (`conf.py`)

### Key Settings

```python
project = "ReScript IntelliJ Plugin"
extensions = [
    "myst_parser",
    "sphinx_copybutton",
    "sphinx_design",
]
html_theme = "furo"
language = "en"
locale_dirs = ["locale/"]
gettext_compact = False          # One .po per source file
myst_enable_extensions = [
    "colon_fence",               # ::: directive syntax
    "deflist",                   # Definition lists
    "fieldlist",                 # Field lists
    "attrs_inline",              # Inline attributes
]
```

### Furo Theme Customization

```python
html_theme_options = {
    "light_logo": "img/logo-light.svg",   # Future: plugin logo
    "dark_logo": "img/logo-dark.svg",
    "sidebar_hide_name": False,
    "navigation_with_keys": True,
    "footer_icons": [...],                 # GitHub link
}
```

### Static Assets

- `_static/css/custom.css` — Language switcher styling, minor overrides
- `_static/img/screenshots/` — Directory for future screenshots (`.gitkeep`)

## 4. Makefile Design

Targets:

| Target | Description |
|--------|-------------|
| `install` | Create venv and install dependencies from requirements.txt |
| `html` | Build English HTML to `_build/html/` |
| `gettext` | Extract translatable strings to `.pot` files |
| `update-po` | Update Japanese `.po` files from `.pot` |
| `build-ja` | Build Japanese HTML to `_build/html_ja/` |
| `build-all` | Build English + Japanese, assemble into `_build/site/en/` and `_build/site/ja/` with root redirect |
| `serve` | Serve `_build/site/` on localhost:8000 |
| `clean` | Remove `_build/` directory |
| `linkcheck` | Run Sphinx link checker |

### Build Output Structure

```
_build/
├── html/          # English build (intermediate)
├── html_ja/       # Japanese build (intermediate)
└── site/          # Final assembled site
    ├── index.html # Redirect to /en/
    ├── en/        # English pages
    └── ja/        # Japanese pages
```

## 5. Language Switcher Design

### Template (`_templates/layout.html`)

Extends Furo's base layout. Injects a language switcher into the footer area using Jinja2:

```html
{% extends "furo/base.html" %}
{% block footer %}
{{ super() }}
<div class="language-switcher">
  <a href="/en/{{ pagename }}.html" {% if language == 'en' %}class="active"{% endif %}>EN</a>
  <span class="separator">|</span>
  <a href="/ja/{{ pagename }}.html" {% if language == 'ja' %}class="active"{% endif %}>JA</a>
</div>
{% endblock %}
```

### CSS Styling

```css
.language-switcher {
    text-align: center;
    padding: 1rem 0;
    /* Active language bold, others normal weight */
}
.language-switcher .active {
    font-weight: bold;
    text-decoration: none;
}
```

## 6. i18n Workflow

```
Source (.md files, English)
    ↓ make gettext
.pot files (message catalogs)
    ↓ make update-po
.po files (locale/ja/LC_MESSAGES/*.po)
    ↓ (manual translation in .po files)
    ↓ make build-ja
Japanese HTML output
```

### Translation Scope (PoC Phase)

Only the following pages will be translated for proof-of-concept:
- `index.md` — Landing page
- `user/installation.md` — Installation guide
- `user/quickstart.md` — Quick start guide

Other pages will fall back to English content when Japanese translation is not available.

## 7. GitHub Actions Workflow Design

### Trigger

```yaml
on:
  push:
    branches: [main]
    paths: ['sphinx-docs/**']
  pull_request:
    branches: [main]
    paths: ['sphinx-docs/**']
```

### Jobs

**On push to main:**
1. Checkout repository
2. Setup Python 3.12+
3. Install dependencies from `sphinx-docs/requirements.txt`
4. Run `make build-all` (builds EN + JA + assembles site)
5. Upload artifact via `actions/upload-pages-artifact@v4`
6. Deploy via `actions/deploy-pages@v4`

**On pull request:**
1. Checkout repository
2. Setup Python
3. Install dependencies
4. Run `make html` (English only, for validation)
5. Run `make linkcheck`

### Permissions

```yaml
permissions:
  contents: read
  pages: write
  id-token: write
```

## 8. Content Strategy

### Information Sources

| Sphinx Page | Primary Source |
|-------------|---------------|
| `user/features/*` | `docs/product-requirements.md` (feature list) |
| `dev/architecture.md` | `docs/functional-design.md` (architecture diagrams) |
| `dev/project-structure.md` | `CLAUDE.md` (project structure) |
| `dev/building.md` | `CLAUDE.md` (build commands) |
| `dev/contributing.md` | `CLAUDE.md` (development conventions) |
| `dev/testing.md` | `CLAUDE.md` (test conventions) |
| `user/installation.md` | `README.md` (requirements section) |

### Content Tone

- **User docs**: Task-oriented, step-by-step instructions, screenshots where helpful
- **Dev docs**: Reference-oriented, code examples, links to source files
- **Both**: Concise, scannable, use tables and lists over prose

## 9. .gitignore Updates

Add to project `.gitignore`:

```
# Sphinx documentation
sphinx-docs/_build/
sphinx-docs/.venv/
*.mo
*.pot
```

Note: `.po` files (translations) ARE committed to version control. `.pot` and `.mo` files are generated artifacts and should be ignored.
