# Requirements: UI テストフレームワーク導入 & マーケットプレイス用スクリーンショット自動撮影

## 背景

- プラグインの JetBrains Marketplace ページに掲載するスクリーンショットを自動撮影したい
- 手動撮影は再現性が低く、リリースごとに手間がかかる
- 同時に、UI テスト基盤を整備して機能のリグレッション検出にも活用したい

## 目的

1. IntelliJ Remote-Robot を使った UI テストフレームワークを導入する
2. マーケットプレイス掲載用のスクリーンショットを自動撮影するテストスイートを作成する
3. 既存のユニットテスト（JUnit 6）と分離して実行できるようにする

## 機能要件

### FR-1: UI テスト基盤

- Remote-Robot を Gradle に統合し、`./gradlew uiTest` で UI テストを実行できる
- 既存の `./gradlew test`（ユニットテスト）には影響しない
- UI テストは `src/uiTest/kotlin/` に配置する
- JUnit 6 (Jupiter 6.x) を使用する

### FR-2: スクリーンショット自動撮影

- テスト実行中に IDE の状態を撮影し、`build/screenshots/` に保存する
- 各スクリーンショットは説明的なファイル名を持つ（例: `syntax-highlighting.png`）
- テストプロジェクト（サンプル ReScript コード）を `src/uiTest/testData/` に配置する

### FR-3: 撮影シーン

マーケットプレイスで訴求力の高い以下のシーンを撮影する:

| # | シーン | 説明 | 訴求ポイント |
|---|--------|------|-------------|
| 1 | シンタックスハイライト | ReScript コードの色分け表示 | プラグインの基本機能 |
| 2 | コード補完 | 補完ポップアップ表示中 | LSP 連携の実用性 |
| 3 | Error Lens | エラー・警告のインライン表示 | 型エラーの即座把握 |
| 4 | インレイヒント | 型推論ヒントの表示 | 型安全性の可視化 |
| 5 | ストラクチャービュー | ファイル内シンボルツリー | コードナビゲーション |
| 6 | Code Vision | 関数の型注釈表示 | コード理解の支援 |
| 7 | JSX サポート | JSX コードのハイライト・補完 | React 開発への対応 |
| 8 | Project View | .resi ネスト・コンパイル済み JS 灰色化 | プロジェクト整理 |
| 9 | クイックフィックス / Intention | Alt+Enter メニュー表示 | コード品質改善 |
| 10 | ホバードキュメント | 型情報・ドキュメント表示 | コード理解 |
| 11 | REPL | インタラクティブ実行環境ツールウィンドウ | 対話的開発 |

### FR-4: テストプロジェクト

- スクリーンショット撮影用のサンプル ReScript プロジェクトを用意する
- `rescript.json` + サンプル `.res` ファイルを含む
- 各撮影シーンに対応するコードを含む

## 非機能要件

- UI テストは CI では実行しない（ヘッドレス環境での実行が困難なため、ローカル専用）
- スクリーンショット生成は自動化し `build/screenshots/` に出力する。Marketplace へのアップロードは Web ダッシュボードから手動で行う（API 未提供のため）
- テスト実行時間: 全スクリーンショット撮影が 5 分以内に完了する
- macOS で動作すること（開発環境）

## 受け入れ条件

- [ ] `./gradlew uiTest` で UI テストが実行できる
- [ ] `./gradlew test` は既存のユニットテストのみ実行する（UI テストを含まない）
- [ ] 11 種類のスクリーンショットが `build/screenshots/` に自動保存される
- [ ] スクリーンショットの品質がマーケットプレイス掲載に十分である（1280x800px 以上）
- [ ] JetBrains Marketplace に screenshot upload API の機能リクエストを提出する
