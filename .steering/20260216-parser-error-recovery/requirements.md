# Requirements: パーサーエラーリカバリ

## 背景

現在の `RescriptParser` は、トップレベル宣言の認識に失敗した場合、トークンを無言でスキップする（`else -> b.advanceLexer()`）。これにより以下の問題が発生している:

1. **エラー表示なし**: 構文エラーがあっても `PsiErrorElement` が生成されないため、IDE 上でエラー箇所が視覚的に示されない
2. **宣言内のエラー無視**: `let = 42`（識別子欠落）のようなケースでもエラーが報告されない
3. **不均衡な括弧への脆弱性**: 閉じ括弧の不足時にパーサーがファイル末尾まで消費してしまい、後続の宣言が認識されない

## 要求内容

### R1: トップレベルの不明トークンに対するエラーノード生成

- トップレベルでキーワード以外のトークンが出現した場合、`PsiErrorElement` でラップする
- エラーメッセージ: `"Unexpected token"` 等の簡潔な説明
- 連続する不明トークンは1つのエラーノードにまとめる

### R2: 宣言内の構造エラー検出

- `let` / `type` / `external` / `exception` の後に識別子が欠落している場合、エラーを報告する
- `module` の後に `UIDENT` が欠落している場合、エラーを報告する
- エラーがあっても宣言ノード自体は生成し、後続のパースを継続する

### R3: 不均衡な括弧からのリカバリ

- `skipToEndOfDeclaration` で閉じ括弧なしにEOFに到達した場合、適切にリカバリする
- モジュール本体の `}` が欠落している場合でも、次のトップレベル宣言を認識できるようにする

### R4: 既存機能の非破壊

- 正常なコードのパース結果は変更しない（既存テスト全パス）
- ストラクチャビュー、コード折りたたみ等の下流機能に悪影響を与えない
- パフォーマンスへの影響は最小限にする

## 受け入れ条件

1. 構文エラーを含むファイルで `PsiErrorElement` が PSI ツリーに含まれる
2. エラー後の正常な宣言が正しく認識される（リカバリ成功）
3. 既存のパーサーテストが全てパスする
4. 新しいエラーリカバリのテストケースが追加されている
5. `./gradlew buildPlugin` が成功する

## 制約事項

- 軽量パーサーの設計方針（トップレベル宣言のみ認識）を維持する
- 式レベルのパースは行わない（LSP に委譲）
- IntelliJ Platform の `PsiBuilder` API のエラー報告機能（`PsiBuilder.error()`）を使用する
