# Requirements: テストカバレッジの拡充

## 背景

現在のテストスイートは `RescriptLexerTest.kt` の9テスト（JSX関連のみ）に限定されている。`src/test-local/` には `RescriptLexerBlogContentTest.kt`（実コード由来の広範なテスト）が存在するが、CI の `src/test/` には含まれていない。

レクサーの9状態・70+トークンタイプ、およびパーサーの7種類のトップレベル宣言に対して、テストカバレッジが不十分である。今後の機能追加（Structure View、セマンティックハイライト等）の安全網として、テストを体系的に拡充する必要がある。

## 目的

1. レクサーの主要トークンカテゴリすべてにテストを追加する
2. パーサーのトップレベル宣言認識に対するテストを新規追加する
3. `test-local` の有用なテストを `src/test/` に統合する
4. 今後の開発でリグレッションを早期検出できる体制を構築する

## スコープ

### 対象

- **レクサーテスト拡充**（`src/test/kotlin/.../RescriptLexerTest.kt`）
  - キーワード認識（`let`, `type`, `module`, `switch`, `if`, `for` 等）
  - リテラル（文字列、数値（10進/16進/8進/2進）、浮動小数点、文字、ブーリアン）
  - コメント（単行、ブロック、ネスト、doc コメント）
  - テンプレートリテラル（バッククォート、`${}` 補間）
  - 演算子（算術、比較、論理、パイプ、アロー等）
  - アノテーション（`@react.component`, `@@deriving`, `@module("fs")` 等）
  - 識別子（小文字、大文字、`_`、型引数 `'a`、ポリバリアント `#Success`）
  - JSX（既存テスト維持 + プロパティ付き、ネスト等の追加）
  - 文字列のエスケープシーケンス
  - レクサー状態遷移の境界ケース

- **パーサーテスト新規作成**（`src/test/kotlin/.../RescriptParserTest.kt`）
  - `let` 宣言（単純、`rec`、関数）
  - `type` 宣言（単純、`rec`）
  - `module` 宣言（通常、`type`、`rec`）
  - `external` 宣言
  - `open` / `include` ステートメント
  - `exception` 宣言
  - アノテーション（`@`、`@@`）
  - 複数宣言の連続パース

- **test-local テストの統合**
  - `RescriptLexerBlogContentTest.kt` の汎用テストを `src/test/` に移動
  - `BLOG_CONTENT_RES` のような大きなテストデータに依存するテストは `src/test/` に統合

### 対象外

- ハイライトテスト（IntelliJ Platform のテストフレームワークが必要で、別作業とする）
- LSP 統合テスト
- UI テスト

## 受け入れ条件

1. `./gradlew test` ですべてのテストが PASS すること
2. レクサーテストが以下のカテゴリを網羅していること:
   - キーワード（主要なもの10+）
   - リテラル（各種数値フォーマット、文字列、文字リテラル）
   - コメント（単行、ブロック、ネスト）
   - テンプレートリテラル
   - 演算子（主要なもの）
   - アノテーション
   - 識別子・特殊トークン
   - JSX（既存 + 拡張）
   - 状態遷移の境界ケース
3. パーサーテストが7種のトップレベル宣言をすべてカバーしていること
4. `test-local` のテストが `src/test/` に統合され、`test-local` ディレクトリが不要になっていること
5. BAD_CHARACTER が発生しないことを確認するスモークテストが含まれること

## 制約事項

- IntelliJ Platform のテストフレームワーク（`BasePlatformTestCase`）は使用せず、単体テスト（JUnit 4）で完結させる（レクサー・パーサーは直接インスタンス化可能）
- テストクラスのパッケージは `com.rescript.plugin.lang` とする
- 既存の `RescriptLexerTest.kt` のテストは削除・変更せず、追加のみ行う
