# Requirements: JSX PSI モデリング

## 概要

ReScript の JSX 構文に対する PSI (Program Structure Interface) モデリングを追加する。現在のパーサーは JSX トークンをスキップしているが、JSX 要素を PSI ノードとして認識することで、コード折りたたみやストラクチャービューなど IDE 機能の基盤を構築する。

## 背景

### 現状
- JFlex レクサーは JSX トークン (`TAG_LT`, `TAG_GT`, `TAG_LT_SLASH`, `TAG_AUTO_CLOSE`, `JSX_TAG_NAME`, `JSX_COMPONENT_NAME`) を正しく生成している
- 軽量パーサーはトップレベル宣言のみ認識し、JSX は `else` ブランチでスキップされている
- JSX の PSI ノードが存在しないため、IDE は JSX 構造を認識できない

### 目的
- JSX 要素を PSI ツリー上でモデル化し、IDE 機能のための構造情報を提供する
- コード折りたたみで複数行 JSX ブロックを折りたたみ可能にする

## 機能要件

### FR-1: JSX PSI 要素型の定義
以下の PSI 要素型を追加する:
- `JSX_ELEMENT` — JSX 要素全体 (開始タグ〜閉じタグ)
- `JSX_SELF_CLOSING_ELEMENT` — 自己閉じタグ (`<div />`)
- `JSX_FRAGMENT` — フラグメント (`<> ... </>`)

### FR-2: パーサーによる JSX 認識
- `TAG_LT` トークンを検出した際に JSX パースを開始する
- 開始タグ (`<tag>`) と閉じタグ (`</tag>`) をマッチングし、`JSX_ELEMENT` ノードを作成する
- 自己閉じタグ (`<tag />`) を検出して `JSX_SELF_CLOSING_ELEMENT` ノードを作成する
- フラグメント (`<> ... </>`) を `JSX_FRAGMENT` ノードとして認識する
- JSX 要素のネストを正しく処理する

### FR-3: コード折りたたみの拡張
- 複数行にわたる `JSX_ELEMENT` および `JSX_FRAGMENT` を折りたたみ可能にする
- プレースホルダーテキスト: `<tag>...</tag>` / `<>...</>`

### FR-4: テストの追加
- JSX パースのユニットテスト:
  - 自己閉じタグ (`<div />`, `<Component />`)
  - 開閉タグ (`<div>...</div>`)
  - ネストした JSX (`<div><span /></div>`)
  - フラグメント (`<> ... </>`)
  - JSX コンポーネント (`<MyComponent prop="value" />`)
  - 式を含む JSX (`<div>{expression}</div>`)
  - 既存テストが壊れないことの確認

## 非機能要件

### NFR-1: パフォーマンス
- 軽量パーサーの設計思想を維持する。完全な JSX バリデーションは行わず、構造の認識のみに留める

### NFR-2: 後方互換性
- 既存のパーサーテストがすべてパスすること
- 既存の PSI 要素型に変更を加えないこと

### NFR-3: エラー耐性
- 不完全な JSX (閉じタグなし等) でもパーサーがクラッシュしないこと
- JSX パースに失敗した場合は従来通りトークンをスキップすること (グレースフルデグラデーション)

## 制約事項

- 意味解析 (型チェック、プロパティ検証等) は LSP に委譲する
- JSX 属性の個別パースは行わない (タグ内のトークンはスキップ)
- ストラクチャービューへの JSX 表示は本タスクのスコープ外とする
