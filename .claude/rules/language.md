# 言語ルール

**以下は強制的な行動指示であり、例外なく従うこと。**

ユーザー向け成果物（公開ドキュメント・ソースコード・Git 履歴・リリース）は **英語** で記述する。一方、authoring/tooling 用の内部ドキュメント（`.claude/`、`.steering/`、`CLAUDE.md`）は **日本語で記述すること**。`.po` の `msgstr` は日本語での記述を許可する。

## 英語で記述するもの（必須）

以下は単独ユーザー環境でも常に英語で記述すること:

- ソースコード（Kotlin, JFlex, XML）
- KDoc コメント、インラインコメント
- コミットメッセージ
- GitHub Release ノート
- `plugin.xml` の `<change-notes>`
- `README.md`
- `docs/` 配下のドキュメント
- `sphinx-docs/` 配下の `.md`（`locale/` 配下の `.po` を除く）
- テスト名、テストコメント

## 日本語で記述するもの（必須）

以下の authoring/tooling 用ドキュメントは **日本語で記述すること**。英語のみで新規作成・全面書き換えしてはならない:

- `.claude/` 配下のすべて（`rules/`, `skills/`, `commands/`, `agents/`, `hooks/`, `memories/` 等）
- `.steering/` 配下のドキュメント（requirements.md, design.md, tasklist.md 等）
- `CLAUDE.md`

**理由:** 単独コントリビュータの認知負荷軽減のため、authoring/tooling の散文は母語（日本語）で統一する。英語化の翻訳コストとニュアンス喪失リスクに見合わない。外部 PR を受け付ける方針に変わった際は、本ルールを再検討する。

### 既存ドキュメントの遡及適用（grandfather clause）

本ルールは **新規作成および今後の編集に対して適用する**。`.steering/` 配下に既に存在する作業履歴ドキュメント（完了済み作業の requirements.md / design.md / tasklist.md 等）は当時の記録として保持し、一括翻訳は行わない。ただし、既存ドキュメントに**加筆・編集する場合は、追記部分を日本語で記述すること**（英語の既存部分に倣って英語で追記してはならない）。

新規に作成する `.steering/[YYYYMMDD]-[NNN]-*/` ディレクトリ配下のドキュメントは、初回作成時点から日本語必須。

### 日本語必須の範囲での例外（英語可）

以下は日本語必須ファイル内でも英語のまま記述してよい（散文ではないため）:

- YAML frontmatter のキー・値（`allowed-tools`, `model: sonnet` 等）
- コードブロック内のシェルコマンド・ソースコード
- ファイルパス・クラス名・API 名・識別子
- 外部ツール/サービスの固有名詞

散文（見出し・説明文・箇条書きの本文）は日本語で記述すること。

## 日本語可の範囲（authoring / tooling 例外）

以下は authoring/tooling コンテキストであり、日本語での記述を許可する（必須ではない）:

- `sphinx-docs/locale/ja/LC_MESSAGES/**/*.po` の `msgstr` フィールド（翻訳本体）

## 禁止事項

- 「英語で記述するもの（必須）」列挙ファイルに日本語を混入させること
- GitHub Release ノート、コミットメッセージ、コードコメントに日本語を使用すること
- `sphinx-docs/**/*.md`（英語本体）に日本語を混入させること（翻訳は `.po` 側で行う）
- 「日本語で記述するもの（必須）」列挙ファイルの散文を英語で記述すること（上記「例外」に該当する識別子・コードブロック等を除く）
