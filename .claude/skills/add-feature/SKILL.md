# 新機能の追加

以下の手順で新機能を実装してください。

## 1. プロジェクト理解
- README.mdを読んで、プロジェクトの全体像を把握する
- architecture.mdを確認して、レイヤー構造を理解する

## 2. 既存パターンの調査
- Grepを使って、類似する既存機能を検索する
- 見つかった実装ファイルを読む
- 以下の点を確認する：
　- サービス層の呼び出し方
　- エラーハンドリングのパターン
　- テストの書き方

## 3. 実装
- 既存パターンに従って、新機能を実装する
- architecture.mdのレイヤー構造を遵守する

## 4. テストと検証

### テストの作成

新機能に対応するテストを `tests/StockTaxApp.Tests/Tests.fs` に追加する。

**既存パターンの参照:**
- `Tests.fs` の既存テストを読み、プロジェクトのテストスタイルを把握する
- `createTransaction` ヘルパー関数（Tests.fs 冒頭）を再利用して Transaction レコードを簡潔に生成する

**命名規則:**
- テスト名は日本語バッククォート形式を使用する: `` [<Fact>] let ``テストの説明`` () = ``
- テストの意図が日本語で明確に伝わる名前にする
- 例: `` ``買って売った場合の損益計算（利益）`` ``、`` ``令和日付の変換テスト`` ``

**テスト構造（AAA パターン）:**
```fsharp
[<Fact>]
let ``テストの説明`` () =
    // Arrange: テストデータの準備
    let input = ...

    // Act: テスト対象の関数を実行
    let result = Module.targetFunction input

    // Assert: 結果の検証
    Assert.Equal(expected, result)
```

**テスト観点:**
- 正常系（基本パス）
- エッジケース（空リスト、None、0件、境界値）
- エラーケース（不正入力、想定外のデータ）
- 計算ロジックの場合は、期待値の算出過程をコメントで記述する

### テストの実行

- `dotnet test` を実行する
- エラーが出た場合：
　- architecture.mdを再確認
　- 既存パターンとの差異を確認
　- 修正して再テスト

## 5. ドキュメント更新
- 必要に応じて、関連ドキュメントを更新する
  実装の検証

implementation-validatorサブエージェントを起動して、実装の品質を検証してください。

サブエージェントには以下の情報を渡してください:
- 実装した機能の説明
- 実装したファイルのリスト
- 関連するスペックドキュメントのパス

検証結果を確認し、必要に応じて修正を行ってください。
