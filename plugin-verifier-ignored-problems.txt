// ── LSP API (com.intellij.platform.lsp.api.*) deprecated in 2026.2 ─────
//
// The LSP integration API was renamed toward client/integration terminology. The
// replacement names shipped in 2026.1.4 and the old ones were deprecated in 2026.2:
//
//   LspServerSupportProvider        -> LspIntegrationProvider
//   LspServerDescriptor             -> LspClientDescriptor
//   ProjectWideLspServerDescriptor  -> ProjectWideLspClientDescriptor
//   LspServer                       -> LspClient
//   LspServerManager                -> LspClientManager
//   EP platform.lsp.serverSupportProvider -> EP platform.lsp.integrationProvider
//
// Unchanged: Lsp4jClient, LspServerNotificationsHandler, LspServerState, and the
// customization/* package — there are no LspClient-prefixed counterparts for these.
//
// The replacement API DOES exist on the current compile target (2026.2.0.1); an
// earlier revision of this file wrongly claimed otherwise, and named the provider
// `LspClientSupportProvider`, which does not exist. The migration is deferred to a
// dedicated follow-up because it touches 13 files and changes method names, not just
// type names (e.g. stopAndRestartIfNeeded -> stopAndRestartClientsIfNeeded).
//
// Deferring is safe: the old interfaces extend the new ones and remain functional on
// 2026.2. In particular LspServerManager.getInstance(Project) still resolves — the
// documented "returns null" breakage applies to project.service<LspServerManager>(),
// which this plugin does not use.
//
// Every call site carries @Suppress("DEPRECATION") (plus "OVERRIDE_DEPRECATION" for
// overrides on deprecated supertypes); the verifier still reports them at bytecode
// level. Remove this entry when the follow-up migration lands.
// Source: RescriptLspServerSupportProvider.kt, RescriptLspServerDescriptor.kt,
//   RescriptLspUtils.kt, RescriptDumpLspStateAction.kt, RescriptLspInstaller.kt,
